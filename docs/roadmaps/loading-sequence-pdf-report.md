# 積込順提案・PDF帳票 Roadmap

- Goal: 選択中コンテナの現在配置から、限定された直線搬入モデルによる積込順を決定的に提案し、積荷一覧と5視点画像を対応番号付きPDF帳票としてローカル出力できるようにする。
- Current progress: 100%
- Last reviewed: 2026-09-17
- Completion condition: 利用者が選択中コンテナについて、提案順・根拠・注意事項、番号付き積荷一覧、現在視点・正面・背面・左面・右面の番号付き画像を含む `.pdf` ファイルをブラウザから取得し、ローカルで内容を確認できる。
- Approval boundary: 外部送信、実在顧客データ、保存Schema変更、搬送機器・作業空間を含む経路探索、公開環境への反映は別途承認を要する。

## Confirmed Boundary

- 対象は選択中コンテナへ現在配置されている積荷だけとし、配置した時刻や操作履歴は使わない。
- 積荷は現在の向きを維持し、開口側の負Xからコンテナ奥の正Xへ、最終Y/Zを保った直線で搬入する前提とする。
- 下段積荷または接触支持物を上段積荷より前にする。複数支持は接触する全支持物を先行させるが、支持安定性は未確認と明記する。
- 対象積荷の開口から最終位置までの直線搬入帯を別積荷が正体積で塞ぐ場合、対象積荷をその別積荷より前にする。
- 先行関係を有向グラフにし、循環がなければトポロジカルソートする。同時に選べる積荷は、奥側、低い位置、幅方向の小さい座標、積荷IDの順で決定する。
- 循環、参照不整合、正体積重複、床より上なのに支持接触を導けない状態では順序を捏造せず、提案不能理由を示す。
- 上下移動、フォークリフト等の搬送機器、作業員、通路、扉厚、斜路、旋回、吊り上げ、固縛、荷崩れ、荷下ろし順、目的地順は評価しない。
- 提案順、帳票用画像、帳票生成状態は派生状態であり、Project、JSON、端末保存、Undo/Redoへ保存しない。Schema `0.1.0` を変更しない。

## Planned Output Contract

- 一覧は積込順番号、積荷名、積荷ID、現在向き適用後の `長さ × 幅 × 高さ mm`、重量kgを含む。
- 画像上の番号は一覧の積込順番号と一致し、積荷色だけに依存しない。
- 正面は開口側の負Xから正Xを見る。背面は正Xから負X、左面・右面は正面からコンテナ内を見る利用者基準とする。
- 「現在視点」は出力開始時のcameraを固定して使い、4つの正投影固定面はcamera操作の影響を受けない。
- 現行の物理判定に不適合がある場合も帳票には状態と理由を記載する。ただし順序計算に必要な参照・重複・支持関係を確定できない時はPDF生成を止める。
- 同じProjectと選択中コンテナからは同じ提案順と固定4面を得る。生成日時と現在視点画像は出力時点に依存する。

## Rollback

積込順エンジン、帳票dialog、帳票scene、PDF生成依存と入口を除去する。Project、Schema `0.1.0`、配置、履歴、保存形式を変更しないためdata migrationは不要で、既存CLPはそのまま残る。
