# Auto CLP Specification

- Last updated: 2026-08-27
- Specification version: 0.2.0
- Status: Active
- Current phase: Phase 1 — ローカル3D手動配置試作

## Purpose

精密機器運送業者が、積荷の寸法、重量、向き、段積み条件と、コンテナまたは車両の寸法、開口部、耐荷重を使い、必要な積載空間と配置可能性を3Dで検討できるようにする。

## Users

- 初期利用者は、実務評価に協力する精密機器運送会社の担当者。
- 将来利用者は、不特定多数の精密機器運送事業者を想定する。
- 成功の主要判断基準は、初期利用者が実案件を模した代表ケースを無理なく入力・確認できる利用体験である。

## Scope

### In Scope

- サーバーを必要とせずPC上のブラウザで動作するローカルWebアプリ。
- 複数の積荷と複数候補のコンテナまたは車両の入力。
- 積荷と積載空間の3D表示、積荷の手動移動と回転。
- 境界、積荷同士の重なり、開口部通過、段積み可否、コンテナ耐荷重、積荷重量、X・Y・Z軸別の固定隙間の判定。
- 端末内保存とJSONファイルによる案件の入出力。
- 後続フェーズでの、必要コンテナおよび積荷配置の自動提案。
- 積荷の複雑な凹凸を、利用者が組み合わせた一つの直方体として登録する運用。

### Out of Scope

- 任意形状メッシュを使った厳密な凹凸ネスティング。
- 搬出順または目的地順を考慮した積み込み順の提案。
- アカウント、クラウド保存、共同編集、外部API連携。
- 一般公開デプロイ、課金、収益化。
- 実運送の安全性、法令適合性、荷崩れ防止を保証する判定。

## Environment and Boundaries

- 対象はWebGL 2を利用できる現行デスクトップブラウザとする。具体的な対応ブラウザ一覧と最低GPU性能は未決定。
- 初期版は静的なクライアントアプリで、サーバー処理と外部送信を行わない。
- 計画技術はTypeScript、React、Three.js、Vite。重い探索処理はWeb Workerへ分離する。
- ライブラリの具体的なバージョンは実装開始時に検証してロックする。
- すべての開発タスクは `C:\Users\seven\projects\auto-clp` を使用し、承認のない別Worktreeを使用しない。

## Functional Requirements

### Cargo

- 各積荷は一意な識別子、表示名、長さ、幅、高さ、重量、段積み可否を持つ。
- 積荷は直方体として扱い、3軸方向を入れ替える回転を可能にする。
- 各積荷は6種類の直交向きから非空の許可向き集合を持つ。新規積荷の既定は、高さ軸をZに保つ2種類の水平向きとする。
- 横倒しまたは天地反転を含む向きは利用者が明示的に許可し、手動回転、自動提案、開口部判定は同じ許可集合だけを使う。
- 複雑形状は、利用者が収まる外接直方体または組み合わせ後の直方体として入力する。

### Container or Vehicle

- 各候補は一意な識別子、表示名、内部長さ、内部幅、内部高さ、開口部寸法、耐荷重を持つ。
- Phase 1では負X側端面に一つの軸整列矩形開口を持ち、床面に接して幅方向中央へ配置する。保存する開口データは幅と高さとする。
- 開口部判定は積荷を許可向きの一つへ固定し、開口面に直角な直線で通す寸法モデルとする。開口内回転、斜め通過、斜路、扉厚、段差、車内旋回、既配置積荷を避ける経路は「経路未確認」とする。

### Placement and Validation

- 利用者は3D空間で積荷を選択し、移動、回転、取り外しができる。
- システムは積載空間外へのはみ出しと積荷同士の重なりを検出する。
- システムは積荷ごとの段積み可否を考慮する。
- 床にない積荷は、同じ高さにある段積み可能な支持上面の和集合が底面を100%覆う場合だけ幾何学的に支持される。支持接触だけはZ軸固定隙間の例外とする。
- システムは積荷重量合計がコンテナ耐荷重を超える場合に不適合を示す。
- 積荷別上載荷重、荷重分布、重心、軸重、床面強度、荷崩れ、固縛、動荷重はPhase 1で計算せず、段積み時は幾何判定に合格しても「構造・安定性未確認」を示す。
- 利用者はX・Y・Z軸それぞれの固定隙間を設定でき、判定に反映される。
- どの許可向きでも `積荷幅 + 2 × Y隙間 <= 開口幅` かつ `積荷高さ + Z隙間 <= 開口高さ` を満たさない場合は不適合とする。床支持面にはZ隙間を要求せず、寸法上通る場合も完全な搬入経路は未確認と明示する。
- 各判定は、理由と対象積荷を利用者が識別できる形で表示する。

### Persistence

- 案件状態を同じ端末内に保存し、再読込できる。
- 案件をJSONとして書き出し、同じ仕様バージョンへ再読込できる。
- 不正または未対応バージョンのJSONを安全に拒否し、既存状態を破損しない。

### Automatic Proposal

- 後続フェーズで、候補コンテナと配置案を自動提案する。
- 目的関数、探索時間、最適性保証、重心・軸重の扱いは未決定であり、ADR 0004がAcceptedになるまで実装要件としない。

## Non-functional Requirements

- 端末外へのデータ送信を行わず、オフラインでも主要機能が利用できる。
- 検証ルールと3D表示を分離し、寸法・回転・衝突・重量判定を自動テストできる。
- 同じ入力に対する判定は決定的である。自動探索で乱数を使う場合はシードを保存する。
- 誤った積載可否を安全保証として誤認させない。近似、未検証、警告、不適合を区別する。
- 初期利用者が代表ケースを入力・再確認できるよう、寸法・重量・警告の視認性と操作取り消しを重視する。
- 実装後は単体テスト、ブラウザ操作テスト、ビルド、型・静的検査を独立した終了コードで検証する。

## Data and State

- 案件データの正規形式はバージョン付きJSONとする。
- 長さ、位置、隙間は整数mm、質量と耐荷重は整数gを正規単位とする。初期UIは寸法をmm、質量をkgで入力し、kgは小数第3位まで受け付ける。
- 寸法と開口寸法は1〜100,000 mm、隙間は0〜10,000 mm、質量と耐荷重は1〜100,000,000 g、配置座標は-1,000,000〜1,000,000 mmとする。
- NaN、無限大、空文字、単位変換後に整数にならない値、範囲外または安全な整数でない値を拒否する。重量合計でも安全な整数範囲を確認する。
- 保存対象には、積荷、コンテナ候補、配置、回転、隙間設定、仕様スキーマバージョンを含める。
- 実在顧客の機密情報を前提とせず、名称欄へ個人情報や秘密情報を保存しないよう表示する。

## Error Handling

- 入力不正、配置不適合、ファイル読込失敗、未対応データ版、描画非対応、探索打切りを区別する。
- 読込失敗時は現在の案件状態を保持し、上書きしない。
- 描画または計算失敗を黙って無視せず、利用者に安全側の状態を示す。
- 必須検証の失敗は後続コマンドの成功で隠さない。検証をまとめる場合、いずれかが失敗すれば非ゼロで終了する。

## Security and Sensitive Information

- 秘密情報、資格情報、個人情報、実在顧客の貨物明細、搬送経路、価格情報をリポジトリ、ログ、テスト、プロンプトへ保存しない。
- 初期版は外部通信と外部書き込みを行わない。
- JSON読込はサイズ、型、値域、スキーマを検証し、実行可能コードとして評価しない。

## Current Phase Completion Criteria

- 複数の積荷とコンテナを入力できる。
- 3D空間で積荷を移動・回転できる。
- 開口部通過、境界、重なり、段積み可否、重量上限、軸別隙間を判定できる。
- 案件を保存・再読込できる。
- 実務利用者が代表ケースを試用できる。
- 必須の単体、ブラウザ、ビルド、型・静的検査が個別に成功し、結果と終了コードが記録される。

## Open Decisions

- 対応ブラウザと最低GPU性能。
- 自動提案の優先順位、許容計算時間、最適性、失敗・打切り表示。
- 代表受入ケース、評価担当、合格基準。

正規単位と値域、Phase 1の開口部モデル、積荷別許可向き、支持と荷重の扱いはADR 0005〜0008で確定した。完全な搬入経路、方向ラベル、部分支持、積荷別上載荷重、重心、軸重、床荷重、荷崩れ、固縛、動荷重が代表ケースで必要になった場合は、後継ADRで範囲を拡張する。
