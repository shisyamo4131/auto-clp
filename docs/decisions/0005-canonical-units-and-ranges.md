# 0005 正規単位、入力精度、値域

- Date: 2026-08-27
- Status: Accepted
- Related specification: Data and State
- Supersedes: None

## Context

寸法、位置、隙間、重量を浮動小数点のまま計算すると、接触や境界で再現しにくい誤差が生じる。初期利用者向け入力は日本の運送実務で扱いやすくしつつ、保存形式は表示単位から独立させる必要がある。

## Decision

- 長さ、位置、隙間の正規単位は整数ミリメートルとする。
- 質量と耐荷重の正規単位は整数グラムとする。
- 初期UIの寸法入力はmm、質量入力はkgとし、kgは小数第3位まで受け付けてグラムへ正確に変換する。
- JSONは表示文字列ではなく、単位を名前に含む整数フィールドを保存する。
- 寸法と開口寸法は1〜100,000 mm、隙間は0〜10,000 mm、質量と耐荷重は1〜100,000,000 g、配置座標は-1,000,000〜1,000,000 mmを受入範囲とする。
- NaN、無限大、空文字、単位変換後に整数にならない値、範囲外の値、安全な整数でない値を拒否する。複数積荷の合計でも安全な整数範囲を確認する。

## Rationale

整数化により境界、接触、JSON往復の判定が決定的になる。mmとkgは初期利用者の入力負担を抑え、内部グラムは小数kgを誤差なく保持できる。明示的な値域は異常入力や描画・計算の破綻を早期に拒否する。

## Impact

- Users: 初期UIではmmとkgを使用する。他単位表示は後続の互換機能として追加できる。
- Data: 例として寸法は `lengthMm`、質量は `massGrams` のような整数フィールドになる。
- Implementation: 入力境界でだけ表示単位を変換し、幾何・重量計算は正規整数で行う。
- Tests: 最小・最大・直前直後、kgからgへの変換、端数拒否、安全な整数、JSON往復を検証する。

## Compatibility and Migration

アプリと永続データは未実装のため既存データ移行はない。将来cm、m、inch、lb表示を追加しても、正規JSONを変更せず入出力境界で変換する。

## Rollback

実装前は本ADRと対応仕様を戻せる。実装後に正規単位を変える場合は、新しいスキーマ版と移行処理を伴う後継ADRで本ADRをSupersededにする。

## Reconsider When

1 mmまたは1 gより細かい精度が代表ケースで必要になる、100 mまたは100 tを超える対象が必要になる、または他単位入力が受入条件になった場合。
