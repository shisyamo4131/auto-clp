# 0032 積荷合成重心の参考可視化

- Date: 2026-09-08
- Status: Accepted
- Related specification: Application Shell and Primary Workflow; Placement and Validation; Planned Terms of Use; Data and State
- Partially supersedes: 0008の「重心を計算しない」境界だけを置換する
- Refines: 0010, 0012, 0025, 0026, 0027

## Context

Phase 1は積荷ごとの整数g重量、コンテナ局所座標の配置、向き適用後寸法を既に保持し、総重量と耐荷重だけを評価している。ADR 0008は、重心、軸重、床荷重、支持反力、構造安定性を入力不足のまま推測しないため、重心を計算対象外としていた。

利用者は手動配置の次段階として、選択中コンテナの幾何中心と、配置済み積荷の重量・位置から求めた現在の合成重心のずれを、数値や合否ではなく3D上の二つの点で直感的に比較したい。各積荷の個別重心位置とコンテナ自重は入力されていないため、計算仮定と非保証範囲を限定する必要がある。

## Decision

- 選択中コンテナの幾何中心を、内寸 `[0, L] × [0, W] × [0, H]` の中央 `(L/2, W/2, H/2)` とする。コンテナ自重は合成重心に含めず、幾何中心を比較基準としてだけ使う。
- 各配置済み積荷の重心は、向き適用後の軸整列直方体の中央と仮定する。ADR 0010の最小角 `positionMm=(x,y,z)` と向き適用後寸法 `(dx,dy,dz)` から、積荷中心を `(x+dx/2, y+dy/2, z+dz/2)` とする。
- 選択中コンテナへ配置済みの積荷だけを対象に、`massGrams` を重みとする3軸の合成重心を求める。未配置積荷、別コンテナの配置、session-onlyの荷室外pose、drag previewは含めない。
- 意味・参照が有効な保存済み配置は、境界不適合または支持条件未確認でも現在の入力状態として計算に含める。物理判定は独立表示し、重心計算が不適合配置を適合、安全または許容と見なしたことにはしない。
- 軸 `a` の倍座標momentを `S_a = Σ mass_i × (2 × position_i,a + orientedDimension_i,a)`、総重量を `M = Σ mass_i` とし、合成重心を `S_a / (2 × M)` とする。許可上限では中間積がJavaScriptのsafe integerを超え得るため、実装は正確な整数集計を使い、表示・scene変換の直前まで有理値を保つ。入力順、奇数mm寸法、負座標で結果を変えない。
- 3D viewportでは、コンテナ幾何中心を赤い固定画面サイズのドット、積荷合成重心を黄色い固定画面サイズのドットとして、viewport内へ投影できる時は積荷より前面に重ねる。二点の画面上の中心が一致する場合は、座標をずらさず、赤い外側ドットと小さい黄色の内側ドットを同心表示する。近接して表示領域だけが重なる場合は各投影中心を維持し、異なる大きさ、輪郭、決定的な重ね順で両方を識別可能にする。ドットはpointer hit、raycast、focus、積荷選択、drag、camera、履歴、dirty状態を変更しない。
- 赤・黄と役割を対応付ける凡例と読み上げ用の同値を一度だけ併設し、色だけで意味を伝えない。赤は異常・不適合、黄は警告・未確認を意味しない。X/Y/Z差、直線距離その他の数値は表示しない。
- 合成重心の正規3D位置がcameraの表示範囲外なら、黄色いドットを画面端へ移動またはclampせず、cameraも自動変更しない。黄色いドットは画面外のままとし、凡例へ非数値の `現在重心は画面外` を示す。camera操作後も同じ正規位置から再投影する。
- 選択中コンテナに配置済み積荷がなければ、赤い幾何中心だけを表示し、黄色い合成重心は表示しない。対象解決または安全な計算に失敗した場合は後述の派生表示状態へ遷移し、古い赤・黄ドット、凡例またはstatusを残さず、0位置、物理的不適合、許容範囲外へ読み替えない。
- 配置追加・更新・取り外し、積荷重量・寸法・向き、コンテナ内寸、選択中コンテナ、新規CLP、Undo/Redo、端末・JSON読込で確定Projectまたは対象が変わるたびに再計算する。初版は未確定drag previewへ追従せず、drop確定後に更新する。
- 幾何中心、合成重心、ドット、凡例、計算状態は派生値とし、Project、Schema `0.1.0`、JSON、IndexedDB、履歴へ保存しない。物理判定Workerの理由・lampへ統合せず、許容範囲または合否判定を設けない。
- 使用上の重要事項は、合成重心が入力重量と直方体中央という仮定による参考表示であること、コンテナ自重、実貨物の偏心、支持反力、軸重、床荷重、構造・安定性、固縛、荷崩れ、動荷重、完全な搬入経路、法令適合性、実積載の安全性を評価・保証しないこと、赤・黄の点が異常・警告・合否・積載可否を意味しないこと、および実際の積込み・運搬は利用者が別途確認して責任を負うことを示す。実装時に内容版を更新し、再確認を要求する。

### Derived display states

| State | Red geometry-center dot | Yellow cargo-COG dot | Legend / non-numeric status |
| --- | --- | --- | --- |
| `no-container` | 非表示 | 非表示 | コンテナ未選択またはコンテナなし。古い派生表示を全消去する |
| `empty` | 表示 | 非表示 | `配置積荷なし` |
| `available` | 表示 | 正規3D位置をviewport内へ投影できる時だけ表示 | 赤・黄の役割。画面外なら `現在重心は画面外` |
| `unavailable` | 有効な選択中コンテナを解決できる時だけ表示 | 非表示 | `現在重心を計算できません`。警告、不適合または0位置を意味しない |

選択中コンテナを解決できない時は `no-container`、有効なコンテナに配置がない時は `empty`、正確な重量momentと有限なscene投影を得られる時は `available`、コンテナは有効だが配置参照・重量moment・表示変換を安全に完了できない時は `unavailable` とする。状態変更では赤・黄の両方を新状態から導出する。

## Rationale

積荷重量、配置最小角、向き、寸法は既存Schemaに揃っているため、積荷だけの合成重心なら保存形式を広げずに決定的な派生計算として追加できる。コンテナ自重を推測せず、幾何中心を比較基準に限定することで、未入力値から見かけ上の精密な総合重心を作らない。

数値差や許容域を示すと、根拠のない合否、安全性または物理精度を示唆しやすい。二つの点と凡例だけに限定し、既存の物理判定lampから分離することで、手動配置の偏りを視覚的に検討する支援と、安全判定の境界を分ける。

## Alternatives

- コンテナと積荷を合算する: コンテナ自重が現行データにない。耐荷重から推定または0扱いせず、必要になった場合は新しい入力、Schema版、旧データ移行を別途決める。
- X/Y/Z差または直線距離を数値表示する: 視覚比較を優先し、初版では採用しない。業務上必要になった場合は単位、丸め、精度、表示位置を別承認する。
- 許容範囲と合否を表示する: 軸別閾値と根拠がなく、安全性を誤認させるため採用しない。
- 物理的不適合な配置を除外する: 修正途中の重量を黙って落とすと現在状態の偏りが小さく見えるため採用しない。物理状態は既存lampで独立して示す。
- 通常の深度付き3D球として描く: 合成重心は積荷内部に入ることが多く見えなくなるため採用しない。物理的な大きさを持たない固定画面サイズの非操作overlayとする。
- drag previewへ追従する: session状態、取消、staleの境界を広げるため初版では採用しない。

## Impact

- Users: 選択中コンテナの中央と配置積荷の重量付き中心を、赤・黄の点と凡例で視覚比較できる。数値、許容域、合否、安全保証は提供しない。
- Data: 既存の `massGrams`、配置、向き、寸法だけを使う。Schema `0.1.0`、JSON、IndexedDBは変更しない。
- Domain: 正確な重量momentと空・計算不能を扱う純粋関数を追加する。総耐荷重評価とは独立させる。
- Scene/UI: 一つのdomain結果をscene座標へ変換し、常に前面の非操作ドットと色以外の凡例を表示する。WebGL障害時の通常作業面停止を維持する。
- Safety: 重心可視化は物理判定理由またはlamp状態を変更せず、実際の積込み・運搬の責任を引き受けない。
- Documentation: 仕様1.5.0、データ契約、受入、運用、ロードマップ、索引、変更履歴を同期する。
- Progress: 独立した5点の重量バランス可視化マイルストーンを追加し、既存の3Dを30点から27点、物理制約を25点から23点へ再配分する。承認時点は未実装0/5のため、進捗を98%から93%へ補正する。

## Compatibility and Migration

保存データの形と既存フィールドの意味を変えないため、Schema `0.1.0`を維持し、移行は行わない。既存JSONと端末保存は通常の検証後に同じ入力から重心を再計算する。旧版は派生表示を知らないだけで、重心結果を保存していない。

将来コンテナ自重、積荷個別の重心位置、許容域または判定設定を保存する場合は、現行値から推測せず、新しいSchema版、入力、旧データの未確認扱い、migration、rollbackを後継ADRで定める。

## Rollback

純粋計算、scene adapter、赤・黄ドット、凡例、関連テスト、使用事項内容版と本ADRに対応する仕様・運用・受入・ロードマップ・変更履歴を一体として戻せる。保存データを変更しないためデータrollbackは不要で、既存の重量・配置・総耐荷重評価はそのまま維持できる。

## Required Verification

- Domain: 単一・不均等重量、中心一致、奇数mm、全6向き、負座標、物理的不適合配置、最大1,000件・上限値、入力順、空、参照不整合、非変異、overflowなし。
- Scene: コンテナ幾何中心と合成重心のdomain-to-scene変換、選択コンテナ分離、未配置・別コンテナ・drag preview除外、空・計算不能での黄点消去。
- UI/browser: 赤・黄の固定画面サイズ、viewport内での前面表示、中心一致時の同心glyph、各投影中心を保つ近接glyph、画面外status、4状態、凡例、色以外の同値、pointer・focus・cargo raycast非干渉、camera、DPR、配置・重量・寸法・向き変更、取り外し、Undo/Redo、コンテナ切替、端末・JSON読込、305 / 320 / 375 px、layout shiftなし、WebGL障害時の通常停止。
- Persistence: 幾何中心、合成重心、ドット、凡例、計算状態をJSON・IndexedDB・履歴へ保存せず、読込後に再計算する。
- Human visual check: 中心一致・近接・偏り・画面外・積荷内部・積荷背面、orbit・pan・zoom、赤・黄と物理判定lampの非混同、凡例理解、狭幅を匿名合成データで確認する。自動試験または開発者確認を実務利用者受入へ読み替えない。

## Reconsider When

コンテナ自重、積荷固有の重心位置、数値差、許容域、軸重、床荷重、支持反力、重心のdrag preview、印刷または実積載の安全判定が必要になった場合。
