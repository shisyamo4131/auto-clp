# 0044 限定モデルによる積込順提案とPDF帳票

- Date: 2026-09-17
- Status: Accepted
- Related specification: Loading Sequence Proposal and PDF Report
- Refines: ADR 0006、0008、0010

## Context

現在の配置は作成できるが、現場で使う積込順と、一覧・3D画像を対応付けた成果物がない。配置操作の順番をそのまま積込順にすると、奥の積荷、下段支持物、手前の遮蔽物の関係を表せない。一方、搬送機器、作業空間、斜め移動、吊り上げ、旋回まで含む完全な経路計画は、現在の直方体・矩形開口モデルから大きく範囲を広げる。

## Decision

- 選択中コンテナの現在配置から積込順を派生し、保存済み順序または配置操作履歴は使わない。
- 現在の向きを維持し、開口側の負Xから正Xへ最終Y/Zを保って直線搬入する限定モデルを使う。上下移動そのものは可能と仮定するが、機器、空間、吊上能力および作業安全性は評価しない。
- 積荷ごとに現在向き適用後AABBを作る。対象積荷の荷室内直線搬入帯は、Xを開口面0から対象AABBの最大Xまで、Y/Zを対象AABBと同じ開区間として扱う。別積荷AABBと正体積で交差する時は対象積荷を先行させる。面・辺・点の接触だけでは遮蔽としない。
- 上面Zと上段底面Zが一致しX/Yに正面積を持つ積荷を接触支持物とし、各支持物を上段積荷より先行させる。単一積荷が上段底面を完全包含する既存の確定支持を優先し、複数支持は全接触支持物を先行させた上で「支持条件未確認」を帳票に残す。
- 遮蔽と支持の先行関係を一つの有向グラフへ合成する。循環がなければトポロジカルソートし、同時候補はAABB最小Xの降順、最小Zの昇順、最小Yの昇順、積荷IDの昇順で決定する。これは一意の正解ではなく決定的な一提案である。
- 循環、積荷参照不整合、同一コンテナ内の正体積重複、床より上にあり接触支持物を導けない状態では順序を提案不能とし、関係積荷と理由を返す。無理に残りを並べない。
- 現行物理判定の境界、隙間、開口寸法、上乗せ禁止、重量等の不適合は帳票に明示する。順序の基礎関係を導ける限り帳票自体は出せるが、適合または安全を意味しない。
- 帳票は選択中コンテナ単位とし、積込順番号、名称、ID、現在向き寸法、重量、物理判定状態、現在視点と正面・背面・左面・右面の番号付き画像、限定モデルと非保証の注記を含む `.pdf` とする。
- 正面は負Xから正Xを見る。左右は正面からコンテナ内を見る利用者基準とする。固定4面は帳票専用camera、現在視点は生成開始時に固定した共有camera snapshotを使う。
- 計算とPDF生成はbrowser内で完結し、外部送信しない。提案順、camera snapshot、画像、PDFはProject、JSON、端末保存、Undo/Redoへ含めず、Schema `0.1.0` を変更しない。

## Rationale

支持と開口からの遮蔽をグラフにすると、単純な奥行sortでは表せない積層関係を説明可能な先行関係として扱え、矛盾も循環として停止できる。保存データを増やさず現在配置から再計算すれば、配置変更後に古い順序が残らず、機能全体を分離してrollbackできる。

## Impact

- Users: 現在配置からコンテナ単位の積込順案と現場共有用PDFを得られる。提案不能時は関係積荷と理由を確認する。
- Data: Schema `0.1.0` と既存JSONを変更しない。すべて派生状態である。
- Safety: 搬送機器、作業空間、旋回、斜路、固縛、荷崩れ、実作業手順、荷下ろし順、目的地順、法令適合性を保証しない。
- Tests: graph、幾何境界、決定性、失敗理由、画像座標、番号対応、日本語PDF、複数ページ、WebGL／PDF生成失敗を検証する。

## Rollback

積込順と帳票のdomain、UI入口、帳票scene、PDF生成処理と依存を除去する。既存Project、配置、履歴、JSON、端末保存にはmigrationを行わない。

## Reconsider When

フォークリフトやクレーンの寸法・能力、搬入時の回転、斜め通過、作業空間、扉厚・段差、積載中の仮置き、荷下ろし順、目的地順、複数作業者、または手動での順序固定を扱う必要が生じた場合。
