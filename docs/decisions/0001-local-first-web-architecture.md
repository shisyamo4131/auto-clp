# 0001 ローカルファーストWebアーキテクチャ

- Date: 2026-08-27
- Status: Accepted
- Related specification: Environment and Boundaries
- Supersedes: None

## Context

利用者の導入負担を下げ、初期はローカル試作としながら将来のWeb公開へ移行できる構成が必要である。3D表示を扱うが、初期版にサーバー、アカウント、外部保存は不要である。

## Decision

TypeScript、React、Three.js、Viteによる静的クライアントアプリを採用する。3D表示はWebGL 2対応ブラウザで行い、探索処理は必要に応じてWeb Workerへ分離する。案件データは端末内保存とJSON入出力で扱い、初期版は外部送信しない。

## Rationale

ローカル開発サーバーだけで試作でき、静的成果物を将来ホスティングできる。UI、3D描画、計算ロジックを分離しやすく、サーバー運用を初期スコープから外せる。

## Alternatives

- ネイティブデスクトップアプリ: 配布と更新の導入負担が高いため初期採用しない。
- サーバー中心Webアプリ: 外部送信、運用、認証を早期に必要とするため初期採用しない。
- Excel/VBA継続: 既存2D操作の制約と3D・探索処理の拡張性から採用しない。

## Impact

- Users: 現行デスクトップブラウザとWebGL 2対応GPUが必要。
- Data: 初期版の案件データは端末内に留まる。
- Implementation: 描画、状態、検証、探索を分離する。
- Tests: 純粋ロジックの単体テストと実ブラウザのUIテストが必要。
- Operations: 初期版にサーバー運用はない。依存バージョンは実装開始時に検証してロックする。

## Migration

将来の公開時は、同じ静的アプリをホスティングする。クラウド保存や認証は別仕様・別承認で追加する。

## Reconsider When

ブラウザ性能が実務データ量を満たさない、ネイティブ機能が必須になる、または共同編集・サーバー保存が承認された場合。
