# 0009 版付き案件JSONとモジュール境界

- Date: 2026-08-27
- Status: Accepted
- Related specification: Persistence; Data and State; Error Handling
- Supersedes: None
- Refines: 0001, 0002, 0003, 0005, 0006, 0007, 0008

## Context

端末内保存、JSON入出力、3D表示、検証、自動提案が同じ案件データを共有する。描画オブジェクトや派生判定を保存形式へ混ぜると互換性とテスト性が低下し、不正JSONの読込で現在状態を破損する危険がある。

## Decision

- 案件スキーマ `0.1.0` をJSON Schema Draft 2020-12で定義し、`schemas/project-0.1.0.schema.json` を機械可読な契約とする。
- 仕様版と案件スキーマ版を分離し、保存データの形または意味が変わる場合だけ案件スキーマ版を更新する。
- 案件JSONはスキーマ版、案件ID・名前、軸別隙間、積荷、候補コンテナ、配置だけを保存する。派生判定、描画、UI一時状態、undo/redoは保存しない。
- ファイル上限は5 MiB（5,242,880 bytes）、積荷1,000件、候補100件、配置1,000件とする。入力途中の保存を許可するため各配列は空にできる。
- JSON Schemaに加え、ID一意性、参照整合性、積荷ごとの単一配置、許可向き、開口と内部寸法の関係、安全な整数合計を意味検証する。
- 不適合な配置は保存できるが、読込後に必ず再判定する。構文、スキーマ、意味検証がすべて成功するまで現在案件を置き換えない。
- domainのモデル、幾何、検証をReact、Three.js、ブラウザI/Oから分離し、純粋関数として実装する。描画、UI、永続化はdomainの規則を再実装しない。

## Rationale

小さな正規契約と再計算可能な派生状態は、JSON互換性、決定性、失敗時復旧を明確にする。構造検証と参照・業務規則の意味検証を分けることで、JSON Schemaの表現限界を補い、具体的な理由を利用者へ返せる。

## Impact

- Users: 入力途中や不適合配置も保存できるが、破損・未対応・参照不正データは現在案件を保持したまま拒否される。
- Data: 正本は整数単位と安定IDを持つ `0.1.0` JSONになり、派生状態は再計算される。
- Implementation: domainはReact、Three.js、I/Oに依存せず、外側の層がdomainへ依存する。
- Security: サイズ上限を解析前に確認し、追加項目を拒否し、JSONをコードとして評価しない。
- Tests: 構文、版、型、値域、参照、向き、開口、合計、トランザクション、往復を独立検証する。

## Compatibility and Migration

アプリと保存データは未実装のため既存データ移行はない。`0.1.x`では意味を壊さない検証・文書修正だけを行う。必須項目、単位、意味を変更する場合は新しいスキーマファイルと明示的な移行処理を追加し、元ファイルを上書きせず変換結果を新しい状態として検証する。

## Rollback

アプリ実装前は本ADR、データ契約、スキーマを一つの変更として戻せる。実装後は保存済みデータを保護するため、旧スキーマ読込と移行経路を残した後継ADRで本ADRをSupersededにする。

## Reconsider When

代表ケースが上限を超える、複数コンテナへ同一積荷を分割する、配置履歴を案件間で共有する、またはクラウド同期が別承認された場合。
