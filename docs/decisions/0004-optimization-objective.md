# 0004 自動配置の目的関数

- Date: 2026-08-27
- Status: Proposed
- Related specification: Automatic Proposal
- Supersedes: None

## Context

自動提案では、コンテナ台数、容積、利用率、計算時間、安定性など複数の目標が競合する。目的関数と打切り条件がないままアルゴリズムを選ぶと、利用者にとって良い提案を評価できない。

## Decision

未決定。実装前に、第一目的、同点時の優先順位、許容計算時間、最適性保証、探索打切り表示、乱数シードを定める。

## Rationale

利用者の実務優先度と代表ケースを確認してから、ヒューリスティック、制約探索、または組み合わせを選ぶ必要がある。

## Alternatives

- 最小台数を第一目的とする。
- 最小容積のコンテナを第一目的とする。
- 計算時間を固定し、最良の既知案を返す。

## Impact

- Users: 提案の良さと打切り状態を理解できる説明が必要。
- Data: 候補コンテナ、優先順位、計算予算の入力が必要になる可能性がある。
- Implementation: アルゴリズム選定は本ADRのAccepted化まで保留する。
- Tests: 決定性、既知ケース、制約遵守、性能上限を検証する。
- Operations: 長時間計算の中断と復旧方法が必要。

## Migration

None。現在は未実装。

## Reconsider When

初期利用者から代表ケース、望ましい提案順位、許容待ち時間が得られたとき。
