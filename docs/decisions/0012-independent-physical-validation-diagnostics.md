# 0012 物理制約の独立診断と集約

- Date: 2026-08-27
- Status: Accepted
- Related specification: Placement and Validation; Error Handling
- Supersedes: None
- Refines: 0003, 0006, 0008, 0011

## Context

Phase 1の低レベル純粋関数は、コンテナ境界、正体積重なり、軸別隙間、矩形開口、幾何支持、総耐荷重を個別に評価できる。一方、修正途中として保存できる境界外配置を案件単位で再判定するとき、境界違反を理由に支持接触まで無効にすると、同じ原因から上段の支持不足と積荷間隙間不足が連鎖して表示される。

利用者が最初に直すべき原因を識別でき、同時に独立した安全上の未確認事項を失わない、決定的な集約規則が必要である。

## Decision

- 物理判定は、案件の意味整合性と対象コンテナを解決できた場合だけ実行する。参照不正、対象コンテナ不在、安全な整数計算不能は物理的不適合と混同せず判定不能とする。
- 対象コンテナへ配置された積荷だけを、境界、pair、開口、支持、耐荷重の順で決定的に評価する。対象配置がない有効なコンテナは理由なしの適合とする。
- コンテナ境界外の配置には境界不適合を付け、その配置自身のコンテナ隙間と支持不足、およびその配置を含むpairの重なり・隙間理由を重ねない。
- 境界外の積荷でも、段積み許可、完全一致する上面Z接触、正面積のXY接触、対象底面の100%被覆を満たす幾何支持関係は診断上認識する。支持接触にはADR 0011のZ・XY隙間例外を適用し、上段へ境界違反由来の支持不足または隙間不足を連鎖させない。この認識は境界不適合を取り消さず、積載可能または安全を意味しない。
- 開口寸法と総耐荷重は配置座標境界から独立して評価する。開口は現在配置向きだけでなく積荷の許可向き集合を使い、少なくとも一つが寸法上通る場合は搬入経路未確認、どれも通らない場合は開口不適合とする。
- 幾何支持に合格した床以外の積荷には、構造・安定性未確認を保持する。物理的不適合理由が一つ以上あれば集約状態は不適合、それ以外で未確認理由があれば未確認、理由がなければ適合とする。不適合時も独立して得た未確認理由を削除しない。
- 理由は安定したcode、対象ID、関連積荷IDを持ち、同じ入力では同じ順序で返す。同一の状態・code・対象・関連IDだけを重複排除し、異なる対象または制約の理由を集約で失わない。
- 判定結果は派生状態であり、案件JSONへ保存せず正規入力から再計算する。

## Rationale

境界違反を直す前の一時配置から派生した支持不足や隙間不足を並べると、利用者は複数の独立問題と誤認しやすい。幾何接触を制約診断のために認識し、境界違反そのものを残すことで、適合性を緩和せず原因を一つに絞れる。

一方、開口寸法、総耐荷重、搬入経路、構造・安定性は境界座標とは独立した制約または未確認事項であり、境界違反があっても保持する必要がある。

## Alternatives

- 境界外の積荷を支持候補から除外する: 下段の境界違反から、上段の支持不足とpair隙間不足が連鎖し、修正順が分かりにくくなるため不採用。
- 最初の不適合だけを返す: 他の独立した不適合と未確認事項を失い、修正後に問題が一つずつ現れるため不採用。
- 不適合時は未確認理由をすべて捨てる: 幾何合格後も残る構造・搬入経路の限界を表示できないため不採用。

## Impact

- Users: 境界違反から派生した連鎖理由を避け、最初に直す対象を識別しやすくなる。独立した重量、開口、経路、構造の理由は残る。
- Data: 案件JSONの形、Schema `0.1.0`、正規入力を変更しない。判定結果は保存しない。
- Implementation: 高位判定は意味検証、対象抽出、固定した制約順、安定した理由code・対象ID・重複排除、状態優先順位を一つの純粋関数で所有する。
- Tests: 空配置、対象不在、対象コンテナ分離、境界外、隙間、重なり、開口、支持、耐荷重、複数理由、境界外supporter、決定性、非変異を検証する。
- Operations: 判定は計画支援であり、搬入経路、構造、安定性、法令、安全性を保証しない。

## Compatibility and Migration

利用者向け物理判定は未公開で、案件Schemaと保存値を変更しないため移行は不要である。既存のメモリ内案件は実装後に本規則で再判定する。

## Rollback

公開前は本ADR、仕様、実装、テスト、文書を一括して戻せる。公開後に理由の依存関係または集約を変える場合は、同じ案件の表示意味を黙って変えず、後継ADRで本ADRをSupersededにする。

## Reconsider When

代表ケースで理由件数の上限、部分評価、修正提案、理由の段階表示、境界外配置を支持として扱わない業務要件が必要になった場合。
