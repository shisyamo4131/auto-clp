# 0020 実行可能な開口診断とdrag集中表示

- Date: 2026-08-30
- Status: Accepted
- Related specification: Placement and Validation; 3D Scene; Automatic Proposal
- Supersedes: ADR 0012の寸法適合時に積荷ごとの `opening-path-unverified` を保持する部分
- Refines: ADR 0004、0006、0012、0019

## Context

Phase 1の矩形開口モデルが確認できるのは、許可向き適用後の積荷Y/Z断面が開口寸法に収まるかだけである。回転、斜め通過、車内旋回、既配置物との干渉を含む連続搬入経路は、必要な経路・姿勢・障害物データと評価器がないため現段階では判定できない。それにもかかわらず、寸法に収まる積荷ごとに搬入経路未確認を理由表示すると、同じ非実装事項が大量に並び、利用者が修正できる不適合や支持条件を見つけにくくなる。

同じ人間試用では、drag対象以外の積荷が通常色のまま残るため、積荷が多いsceneで操作対象と支持候補を追いにくいことも確認された。

## Decision

- 許可向きのどれでも矩形開口の幅・高さに収まらない場合は、従来どおり `opening-no-fitting-orientation` を積荷ごとの不適合理由として表示する。
- 寸法に収まる場合は、積荷ごとの `opening-path-unverified` を生成・保存・Worker転送・表示しない。現段階で実装できない搬入経路要件を、個別の確認項目として列挙しない。
- 完全な搬入経路と実積載の安全性を保証しない範囲説明は、物理判定と自動提案の恒常的で簡潔な注意として維持する。これは積荷ごとの理由件数には含めない。
- 具体的な搬入経路要望と評価に必要な入力が将来確定した場合だけ、後継ADRでデータ、判定、表示、移行を設計する。
- fine-pointer drag中は、操作対象の積荷を床、単独支持、支持条件未確認、不適合、荷室外の状態色で表示する。対象以外の積荷は面をほぼ透明な中立色、辺を灰色の点線にして、操作対象の形状を優先する。
- drag previewが示す支持候補は、面の低彩度を維持したまま、単独支持候補を緑、支持条件未確認候補を黄の点線で示す。コンテナ線枠と開口線枠は変更せず、色だけに依存しない固定高statusを維持する。
- drop、取消、pointer capture喪失、描画更新のいずれでも通常色・透明度・辺表示へ復元し、Project、JSON、履歴へ視覚状態を保存しない。

## Rationale

利用者が修正できる事実だけを個別理由にすれば、理由件数と一覧は行動可能性を保てる。安全範囲の明示は恒常的な注意で維持できるため、非実装評価を積荷数だけ重複させる必要はない。drag中だけ周辺表示を弱めることで、積荷を消さずに空間関係を残し、支持候補と操作対象を追いやすくできる。

## Alternatives

- `opening-path-unverified` を折りたたむ案は、件数と集約状態へ非実装項目が残り、修正可能な理由との区別が弱いため不採用。
- 搬入経路に関する注意をすべて削除する案は、寸法適合が経路・安全保証に見える可能性があるため不採用。
- drag中に他積荷を完全に非表示にする案は、支持・干渉関係を判断できなくなるため不採用。
- 支持候補だけ通常の塗り色で強調する案は、積荷が密集したsceneで対象と候補の面が競合するため不採用。

## Impact

- Users: 寸法適合した積荷ごとの重複メッセージが消え、修正が必要な開口不適合と支持理由へ集中できる。drag中は対象以外が透過・点線になり、支持候補を区別できる。
- Data: `opening-path-unverified` は派生理由から削除する。Project、JSON、Schema `0.1.0`、保存データ、進捗は変更しない。
- Implementation: domain理由型と生成、Worker protocol、物理判定・自動提案表示を更新し、Three.jsにdrag中だけ使う点線outlineを追加する。
- Tests: 寸法適合時に理由0件、寸法不適合の専用理由、支持理由の保持、Worker拒否境界、自動提案preview・適用、drag中の透過・点線と終了時復元を検証する。

## Compatibility and Migration

保存データ移行はない。判定理由とdrag集中表示は非永続の派生状態であり、既存Projectは再判定時に新しい理由集合を得る。旧Worker応答に `opening-path-unverified` が含まれる場合は不正応答として破棄し、現行Workerで再試行する。

## Rollback

理由型、生成、Worker protocol、表示copyへ `opening-path-unverified` を戻し、drag中の点線outlineと周辺透過を外す。Project Schemaと保存データのrollback migrationは不要である。

## Reconsider When

搬入経路、姿勢列、経路上の開口・障害物、車内旋回、経路探索、または積荷画像を使う識別表示に具体的な利用者要望と入力契約が確定した場合。
