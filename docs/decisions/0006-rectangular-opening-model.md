# 0006 初期開口部モデルと通過判定

- Date: 2026-08-27
- Status: Accepted
- Related specification: Container or Vehicle; Placement and Validation
- Supersedes: None
- Refines: 0003

## Context

開口部の完全な形状、オフセット、斜路、搬入中の旋回、既配置積荷を含む経路探索には追加データと複雑な連続衝突判定が必要である。Phase 1では、入口を通せない寸法または向きを確実に識別する最小モデルが必要である。

## Decision

- Phase 1の候補コンテナまたは車両は、負X側の端面に一つの軸整列矩形開口を持つ。
- 開口部は床面に接し、コンテナ幅方向の中央に配置する。データ項目は `openingWidthMm` と `openingHeightMm` とする。
- 通過判定は、積荷を一つの許可済み直交向きに固定し、開口面へ直角な直線で搬入するモデルとする。
- 積荷は床支持のまま通過するものとし、`積荷幅 + 2 × Y隙間 <= 開口幅` かつ `積荷高さ + Z隙間 <= 開口高さ` なら寸法上通過可能とする。床との接触面にはZ隙間を要求せず、等しい場合は合格とする。
- 開口内での回転、斜め通過、傾斜路、扉厚、段差、車内での旋回、既配置積荷を避ける経路は判定しない。これらを必要とする案件は「経路未確認」と表示する。
- どの許可向きでも矩形断面に収まらない場合は不適合とする。寸法上通る場合も、完全な搬入経路や作業安全を保証しない。

## Rationale

固定向きの矩形断面判定は決定的に試験でき、明らかに通らない積荷を検出する。扱えない経路要素を未確認として明示することで、単純モデルを実運送の保証と誤認させない。

## Impact

- Users: 初期版では入口幅・高さを入力し、複雑な入口や旋回は別途確認する。
- Data: 開口位置と形状はPhase 1の固定規則であり、JSONには幅と高さだけを保存する。
- Implementation: 許可向きごとのY・Z包絡を純粋関数で比較し、`pass`、`fail`、`unverified-path`を区別する。
- Tests: 幅・高さの等値、1 mm超過、隙間、向き変更、全向き不適合を検証する。

## Compatibility and Migration

アプリと永続データは未実装のため既存データ移行はない。将来、開口の面、オフセット、多角形、経路を追加する場合はスキーマ版を上げ、矩形・負X・床接触・中央配置を既定値として既存データを維持する。

## Rollback

実装前は本ADRと対応仕様を戻せる。実装後は保存済みデータとの互換性を維持する後継ADRで変更する。

## Reconsider When

代表ケースに側面扉、オフセット開口、斜路、入口旋回、または既配置積荷を考慮した搬入順が必要になった場合。
