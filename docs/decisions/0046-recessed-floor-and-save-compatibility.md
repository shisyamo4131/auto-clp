# 0046 段落ち床と保存互換性

- Date: 2026-11-04
- Status: Accepted
- Related specification: 1.15.0 段落ち先行実装
- Refines: ADR 0009、0010、0013、0014、0019、0044（段落ち対象のみ）

## Decision

ユーザーが採用した長方形一か所の段落ちを荷室構造として実装する。通常床Z=0、低い床Z=-depthMm、天井Z=内部高さを維持する。開始X/Yは0以上、長さ・幅・深さは正の整数mm、深さ上限100,000 mm、XYは荷室内に収める。これは入力上限であり実車寸法の保証ではない。

底面が段落ちに一部だけ重なる積荷は、接触辺のみの場合を除き確定拒否する。低床より下への食込みも拒否する。drag、座標、回転、積荷寸法変更、床編集、読込・書出しに共通検証を適用する。床編集で既存積荷の足元高さが変わる場合は移動を自動補正せず拒否し、先に積荷を移動・取り外す。無効な操作は配置・履歴を変更しない。

## Compatibility

平床の既存0.1.0はそのまま読み書きする。初めて段落ちを有効にする確定操作で0.2.0へ移行し、登録配列順にcargoNoを付与する。0.2.0ではcargoNoとnextCargoNoを保存し、削除で欠番を再利用しない。CSV置換は新規番号を割り当てる。Undo/Redoは採番上限を巻き戻さず、形式を0.1.0へ戻さない。旧ファイルそのものは変更しない。

端末保存はcurrent-project-v2を使い、従来current-projectは退避として残す。新枠が未作成の時だけ旧枠を読む。新枠の破損を旧枠への黙った復帰で隠さない。削除は新枠へnullを保存し、旧保存が再登場しないようにする。旧枠には機密データが残り得るため、完全消去はブラウザのサイトデータ削除で行う。

旧版は0.2.0を扱えない。ロールバックには退避した0.1.0 JSONまたは旧枠を使用し、新形式から段落ちを消して平床化する変換は提供しない。

## Scope and Limits

0.2.0の物理判定では開口寸法による不適合を生成しない。旧平床0.1.0の開口判定・帳票は従来動作を維持する移行段階である。段落ちコンテナの旧積込順・PDF入口と中心・重心表示は理由付き停止。上面図PDF、複数開口、実間隔表示、顧客管理番号欄、全CLPの積込順廃止、新規上乗せ禁止の初期値変更は後続作業。

## Verification

境界±1 mm、負の床高さ、天井維持、跨ぎ拒否、床編集拒否、保存往復、旧形式からの移行、採番Undo、保存枠fallbackを単体試験に含める。ブラウザで入力、背高荷配置、座標エラー、保存・再読込、実pointerで跨ぎ表示と復帰を検証する。実車・先方の業務受入は別途必要。
