# 0019 支持面snapと支持条件未確認

- Date: 2026-08-30
- Status: Accepted
- Related specification: Placement and Validation, Automatic Proposal
- Supersedes: ADR 0008の「複数支持面の和集合が底面を100%覆えば幾何支持成立」とする規則
- Refines: ADR 0010、0011、0012、0015、0017、0018
- Refinement: ADR 0020 changes drag candidate emphasis to dotted focus outlines and removes the unrelated per-cargo opening-path diagnostic.

## Context

Phase 1の3D dragはX/Y床面移動だけでZを保持していたため、積荷を別の積荷上へ置くには座標dialogで上面Zを計算する必要があった。人間評価では、主作業面である3D上で段積みを直接組み立てたい要望が確認された。

ADR 0008は、同一高さにある支持可能面の和集合が対象底面を100%覆えば幾何支持成立とした。しかし、複数台への橋渡し、支持台間の隙間、張り出しは、直方体の接触だけでは構造剛性、支持位置、重心、許容支持間隔を判断できない。単一支持と同じ成功区分にするべきではない。一方、修正途中の配置を強制的に戻すと、既存のrepair-in-progress方針と3D作業の連続性を失う。

## Decision

- 床より上の積荷について、支持可能な単一積荷の上面が対象底面とZで完全一致し、向き適用後の底面をX/Y両軸で完全包含する場合だけ、幾何学的な単独支持成立とする。等値を含み、辺・点だけの接触は数えない。
- 支持可能面との正面積接触が一つ以上あるが、複数支持、支持台間の隙間、張り出し、または支持不可面との混在を含む場合は、不適合へ落とさず `support-conditions-unverified` とする。構造剛性、支持位置、重心、許容支持間隔の確認を促す。
- 接触する支持可能面がない、Zが一致しない、支持不可積荷だけに接触する、または正体積で立体重複する配置は不適合とする。単独支持、未確認、不適合のいずれも安全保証としない。
- 単独支持または支持条件未確認を構成する正面積接触には、支持接触としてZおよび接触投影のX/Y隙間例外を適用する。支持不可面だけの接触には適用しない。
- fine-pointer dragでfootprintが荷室床面と正面積で重なる場合、支持可能面がなければ床Z=0へsnapする。支持可能面があれば、重なる候補の最も高い上面Zへsnapする。
- 単一上面が対象底面を両軸で収容できる場合は、対象底面をその上面内へ完全包含できるX/Y範囲に制限する。収容できない場合はZだけを仮snapし、X/Yを制限しない。荷室外poseのZは変更しない。支持不可面だけにはsnapしない。
- drag previewは床、単独支持、支持条件未確認、不適合、荷室外を色と固定高statusで区別し、接触候補を強調する。不適合も既存どおり修正途中として保存でき、一回のdropを一回の配置履歴とする。
- 自動提案v1は床置きまたは単独支持成立だけを採用し、`support-conditions-unverified` を含む案を生成しない。

## Rationale

単一の完全包含面は整数mmのAABBで決定的に判定できる。複数支持や張り出しを未確認として残せば、利用者は3D上で配置を組み替えながら、現在のモデルでは判断できない構造条件を誤って適合と受け取らずに済む。支持可能面が小さい場合にX/Yを拘束しないことで、隣接する複数支持へ橋渡しする調整も妨げない。

## Alternatives

- 複数面の和集合が100%なら単独支持と同じ幾何合格にする案は、支持間隔と剛性を無視して確実性を過大表示するため不採用。
- 張り出しまたは複数支持をすべて不適合にする案は、治具や業務判断を伴う配置を修正途中として検討できないため不採用。
- 不適合dropを元位置へ戻す案は、既存の修正途中保存と人間評価で採用した操作方針に反するため不採用。
- 自由な連続Z dragは、正確な接触高さと既存の整数mm座標契約を保証しにくいため不採用。

## Impact

- Users: 積荷を3D上で支持面へ直接置ける。単独支持は面内で安定して移動でき、小さい支持面や橋渡しは未確認表示のまま調整できる。
- Data: Project、JSON、Schema `0.1.0`は変更しない。判定理由とdrag previewは派生状態である。
- Implementation: 純粋な支持接触区分とsnap位置解決を追加し、Worker理由protocol、物理判定UI、自動提案filterへ反映する。
- Tests: 単一包含の等値と±1 mm、片軸張り出し、複数支持、支持台間隙、支持可否混在、辺・点接触、Z不一致、立体重複、床fallback、drag preview/drop、Undo/Redo、自動提案除外を検証する。

## Compatibility and Migration

保存データ移行はない。既存Projectは読込後に新しい派生規則で再判定される。従来 `support-not-full` だった正面積の張り出しは `support-conditions-unverified` となり、複数面の100%被覆も単独支持ではなく未確認となる。接触する支持可能面がない配置は `support-contact-invalid` となる。

## Rollback

support snapを外し、3D dragのZ保持へ戻す。物理判定はADR 0008の和集合100%規則、旧 `support-not-full` 理由、自動提案の旧候補許可へ戻す。Project Schemaと保存データのrollback migrationは不要である。

## Reconsider When

積荷別上載荷重、支持点・支持範囲、重心、許容支持間隔、治具、パレット、連続Z操作、touch drag、または自動提案での複数支持が必要になった場合。
