## 当日の進め方

時間を区切る必要はない。相手の関心がある操作を優先し、説明し過ぎず最初に迷う場所を見る。

1. 完成例を読み込み、A/Bのタブを切り替える。「今のExcelでやっている検討が、こう見えると役立ちそうですか」と聞く。相手の車両寸法をその場で入力する必要はない。
2. 体験用を読み込み、05をA、10をBへ配置してもらう。未配置の積荷は共通であり、Aで両方を積む必要はない。他のコンテナに配置済みの積荷は、切替先で扱う。
3. 選択・移動・床面回転・Undoを試してもらう。マウスのホイールは拡大縮小、空いた部分の左ドラッグは視点回転、Ctrl付き左ドラッグは視点の平行移動。迷ったらメニューの「操作方法」を一緒に見る。
4. 正確な位置へ戻したい場合、05をA、10をBで選び、座標入力からそれぞれX=400、Y=700、Z=0 mm、元の向きにする。体験を最初からやり直す場合は体験用JSONを再読込する。
5. 必要なら重なり説明用を読み込み、Aの判定詳細から理由を確認する。05の位置をX=400、Y=700、Z=0 mmへ戻すと完成例になる。JSON読込自体はUndoで戻せないため、読込直後のUndoを修正操作に使わない。
6. 完成例へ戻し、コンテナごとに「積込順・PDF帳票」→「5視点画像を生成」→「PDFを出力」。出力名は固定なので、A/Bを区別する名前でPCに保存する。帳票は選択中コンテナだけで、2つのコンテナの搬送順や目的地順は提案しない。
7. 最後にExcelとの比較を聞く。慣れたExcelの操作を失っていないか、紙やPDFで誰に何を伝えたいかを優先する。

50 mmの隙間を設定しているため、壁や別の積荷にぴったり寄せる操作で隙間不足となる場合がある。判定が出たら「なぜか」を一緒に確認し、少し離すか座標を直す。側面スナップのON/OFFは隙間ルールを変更しない。

相手の主業務は大型トラック輸送だが、現行アプリの登録対象はコンテナ。荷室の見える化・配置検討としての感想を聞き、車両対応を実装済みとは説明しない。車両自重、軸重、床強度、エアサス、振動、固縛、荷崩れ、完全な搬入経路を評価しない。黄点は入力重量と直方体中心を用いた積荷だけの参考重心で、赤点との近さを安全の合否にしない。自動配置は通常画面では提供していない。

## 段落ちLocal検証用への移行 2026-11-04

[05-local-recessed-floor.json](05-local-recessed-floor.json)は01-completeを複製し、現行Schema 0.2.0へ移行した架空データ。元の4ファイルは保持する。Localの `http://127.0.0.1:4174/` で「JSONから読込」を使う。固定Noは1〜10、次番号11。10個を各5個ずつ配置、総重量7,100 kg、天地無用・上乗せ禁止と50 mm隙間を維持する。

| 対象 | 検証用変更 |
| --- | --- |

| No.3 | 高さを2,700 mmへ変更。天井Z=2,400に対し上端Z=2,300、天井隙間100 mm |
| B | 段落ちX=3,700/Y=50、長さ2,200/幅1,150/深さ300 mm。No.6をZ=-300へ配置 |
| No.6 | 高さを2,600 mmへ変更。上端Z=2,300、天井隙間100 mm |

実車の形状・寸法ではない。全幅と片側の段落ちを比較するための検証値。AのNo.3を選び「座標を微調整」でX=1,999を入力すると跨ぎ拒否を確認できる。元のX=2,200/Y=150/Z=-400は保持される。実pointerでも段差境界へ動かして赤色プレビューと復帰を確認できる。最初へ戻す時はこのJSONを再読込する。PDFは段落ち対応待ちのため出力できない。
